# 业务绑定、发起与结果处理

## 复用业务模型的审批能力

先检查模型已有的 `workflow`、投射 Action、接口和表单。绑定引用可用的流程定义，业务开发只处理记录、状态、表单、参与人和操作权限，不新增引擎路由或维护另一套待办。

| 模型配置 | 应用侧核对 |
| --- | --- |
| `workflow.isEnabled` | 是否启用模型的审批操作及投射资源 |
| `workflow.bindings[].processId` | 已发布且在目标环境可用的流程标识 |
| `workflow.bindings[].statusField` | 真实业务状态字段，与字段类型及字典取值一致 |
| `workflow.bindings[].statusMap` | 流程状态到业务值的映射，值使用当前契约中的 `code` 等属性 |
| `workflow.startMode` | 模型页面采用的发起方式，按目标版本支持值配置 |
| `workflow.formDataMode/formDataMapping` | 传入流程的表单数据及映射，限制为审批需要的字段 |

当前模型投射读取 `bindings[0]`，不能仅因配置是数组就推断已支持一条记录任意选择多个流程。`statusMap` 的 `pending` 用于发起时状态，回调使用 `processing/approved/veto/withdrawn/suspended/canceled/terminated` 等键；页面还可能引用 `draft/submitted`。它们是绑定契约的键，业务字段的实际值由应用定义，不把“驳回”的键随意改成 `rejected`。只配置业务需要且目标版本支持的状态，并验证页面与后端一致。

`.business.json` 的 `workflow` 外层 Schema 目前较宽松，结构校验通过不能证明这些嵌套字段有效。使用配套业务模型指南，检查实际投射和运行结果；不手工复制已投射的同名 Action、接口、回调逻辑流或页面。

## 发起与表单

模型生成的 `startProcess` Action 输入形态如下。它是 Action 输入片段，不是任意 HTTP 发起接口的完整请求；实际 URL、外层封装和主键类型使用目标模型已导出的契约。

```json
{
  "params": {"record": {"id": "actual-record-id"}},
  "data": {"formData": {"actualField": "actualValue"}}
}
```

发起前由后端检查记录归属、允许状态、可修改字段和发起权限；隐藏按钮、只读控件均不替代这些检查。调用正式 Action Runtime 或已投射接口，保留其事务、授权与失败语义。不要先在客户端写“审批中”再尝试发起，也不要绕过正式入口直接写审批表。

`submitTask` 与 `initTaskForm` 还要求实际 `instanceId/taskId`，办理操作还带 `action`。从正式任务上下文取得这些值；不能只凭业务记录 id 推断当前可办任务。复用审批表单及其允许操作，不自行枚举所有任务按钮。

发起人与候选人标识按公开接口要求提供。员工 id、登录用户标识和部门/岗位主体不是同一类型；使用已有身份关联和参与人选择能力。员工没有关联登录用户时应按实际契约报告，不把员工 id 当成用户 id，也不回退管理员。

## 结果、权限与恢复

先明确平台已完成的状态同步、事件及通知。只有额外业务副作用才新增处理；需要在审批完成后执行时，优先订阅 `workflowApproved/workflowRejected` 等正式事件，按业务模型事件契约处理重复交付。发起或办理接口成功返回不等于整个流程已经通过。

结果处理应核对业务记录、实例和提交轮次，避免旧轮次或重复结果重复入账、重复出库。依赖平台已有的结果顺序及状态投射；业务副作用失败时使用正式恢复入口，不直接篡改流程实例或投递记录。

查看业务记录、查看流程、发起和办理分别核对权限。覆盖无权用户直接调用、同角色不同主体、不可办任务、重复提交、发起失败回滚、结果回写失败，以及目标流程确实支持的通过、驳回、撤回等操作。

## 统一入口与表单边界

使用正式 `FlowInstanceService.start(FlowStartCommand)` 或公开发起接口。引擎与接入方式由平台统一路由；业务代码不按 `RESULT_ONLY` 等模式复制发起链路。发起结果与可用操作以正式响应为准，不把已发起当作已审批完成。

`custom` 字段目录只提供设计时字段和规则。高代码业务负责为实例提供与描述中字段名、值类型一致的数据，并在业务页面和后端落实权限；没有 `FlowFormService` 不表示可以用空表单冒充已对接。部署后修改、显式重新部署与接管保护沿用标准流程管理。

依据：业务模型的 WorkflowBusinessActionNormalizer、workflow 投射及内置审批应用的业务绑定与任务表单契约；源码可用时用于核对，普通消费项目无需拥有这些实现文件。
