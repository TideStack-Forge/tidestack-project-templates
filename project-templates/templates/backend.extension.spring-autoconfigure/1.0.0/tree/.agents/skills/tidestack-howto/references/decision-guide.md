# 开发路线与判断案例

| 路线 | 适用条件 | 组合 |
| --- | --- | --- |
| A 业务模型 | 对象、关系、标准维护和视图由现有能力表达 | 业务模型与投射资源，按需补配置 |
| B 模型加代码 | 对象契约成立，少量操作有复杂事务、算法或外部协作 | Action 定义＋Java Handler/逻辑流，通过 BusinessActionRuntime 执行 |
| C 定制接口与服务 | 专门协议、读模型或运行语义无法合理纳入模型契约 | Controller/Service＋必要数据模型、授权和实际需要的页面 |
| D 专项能力 | 人工审批、后台事实处理、集成、通知或统计 | 复用对应能力，与模型和 Java 组合 |

路线可组合。缺运行依赖、版本或扩展点的证据时给出条件，不能凭有 Schema 推断可交付。

| 需求 | 判断要点 |
| --- | --- |
| 仓库、物料与资料引用 | 优先 A，关联和联合唯一不自动要求全高代码 |
| 单据提交、跨对象校验 | 先评估 B，确认正式事务边界和回滚；不因出现事务重写整套 CRUD |
| 库存扣减、防重复 | 核验锁/条件更新、幂等与事务保证，按真实缺口选择实现 |
| 签名 ERP 回调 | C 处理协议，后续可调用模型 Action；明确签名认证，不能靠匿名绕过安全 |
| 审批待办 | D，区分审批与自动逻辑流，检查业务绑定、身份和状态回写 |
| 外部遥测只读数据 | 先明确数据归属和迁移权限，不默认创建存储表或全套 CRUD |
| 标准列表加复杂按钮 | B＋UI Schema 往往足够，后端复杂不必引入微前端 |
| 重交互编辑器 | 评估组件/微前端，仍复用平台接口和权限 |

业务持久化复用数据模型；平台正式的只读统计 SQL 按统计能力的权限和只读约束评估。目标基线的统计手册记载上下文、预览和发布链路限制，应查部署版本，不能把保存草稿视为发布。

## 参照平台内的应用实践

| 应用层参照 | 可迁移到业务应用的做法 | 应用边界 |
| --- | --- | --- |
| 组织管理 | 复用已命名的编辑 Schema、显式传入记录标识、按真实组织主体校验权限 | 不把组织底层存储或通用主体框架复制到业务模块 |
| 用户与角色管理 | 对齐用户/角色标识、选择器值形态及权限配置回读 | 不为每个功能重建角色编辑器或授权决策器 |
| 文档管理 | 业务接口复用已有领域服务与对象访问检查，弹窗通过已注册页面路由打开 | 对象 ACL 是该领域的语义，不作为所有 CRUD 的强制步骤 |
| 内置审批及其业务绑定 | 复用发起、任务表单、状态同步和结果事件 | 引擎接入、平台待办存储和投递设施不列为普通开发任务 |
| 平台现有通知消费者 | 使用员工/地址入口、检查发送结果，复用已有可靠通知订阅 | 只实现接收规则和业务幂等，不复制通知账本或恢复调度 |

这些参照用于确认公开入口、资源组织和实际行为；需要时再定位具体文件，不要求消费项目持有平台源码。示例所在模块已使用某项能力，不代表目标应用已安装或目标版本已完整支持。

## 建议的边界

仅为真实缺口编写 Java、组件或公开扩展实现；主键生成器、插件、装饰器和权限解析器是可用的应用扩展，但不要求每个功能都实现。新增审批节点类型或修改平台通用授权、资源加载、投递状态机属于平台维护，不混入普通业务开发清单。

定制接口路线仍沿项目既有 Controller/Service、数据模型和异常契约实现；按任务分别推荐现有专项 Skill。
