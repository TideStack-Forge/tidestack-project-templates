# 表单容器与用户文案

## 容器与动作

只为明确视觉分组使用 panel。列表、页面和表单不要连续嵌套相同边框、标题与留白，优先已有 page、布局和表单层级。

| form 所在位置 | 处理原则 |
| --- | --- |
| 独立页面或普通容器 | 通常先用 `title: ""` 去无意义标题；保留必要的表单包裹和动作区域 |
| dialog/drawer | 核对目标基座是否已自动去包裹；按实际结果避免重复容器，核对宿主动作与 form 提交的绑定 |
| 自定义内联表单或手工动作区 | 仅在 actions 有明确宿主和提交目标时去包裹，验证提交、校验和失败状态 |

不能全局替换 `wrapWithPanel: false`。某些 form 渲染路径在去掉 panel 后不会渲染原 panel footer 中的 actions。`title: ""` 与移除包裹的语义不同；先检查目标 AMIS 版本和基座转换，再调整。

## 描述与帮助文字

description、hint、remark、tooltip 等面向用户的内容只解释业务含义、填写要求、操作后果或可执行的解决办法。没有额外用户价值就省略；不为填满模板而重复标题、label 或显然可见的动作。

- 可以：数量的计量单位、合法范围、提交后是否可修改、用户能执行的错误恢复。
- 不应出现：接口由哪个类实现、为什么选这个控件、字段映射方案、待开发能力、AI 的编辑思路、临时测试账号或调试建议。
- 开发解释放源码注释和开发文档；管理员配置页面可解释配置后果，但仍不展示实现过程。

从用户视角检查每条文字：它是否帮助当前用户理解或完成这一步？删除后不影响使用的实现说明应移出界面。
