# 页面交互验证

验证实际目标基座，不只在独立 AMIS playground 中观察。首先检查包资源已加载、UI Model 路由与 wrapper name 对应。

按功能选择必要场景：首次加载、查询、分页、空结果、接口失败、无权限、禁用态、表单校验、重复提交、提交失败后保留输入、成功后刷新与返回。独立 form 和 dialog/drawer form 分别确认 actions 可见、提交目标正确以及关闭行为。

数据域验证使用带代表性的记录，不只空表单。检查新增/编辑/详情是否串值、隐含字段是否误提交、行操作是否使用当前行、刷新是否命中实际 CRUD。业务失败显示用户可行动的消息，不泄露堆栈和原始凭据。

权限用最小角色直接请求 API，再检查菜单和按钮表现。数据范围核对列表、详情、count 和导出；页面隐藏敏感列不代表 API 没有泄露。

交付修改的资源路径、实际接口契约、已执行交互和尚缺的后端/环境条件。没有运行环境时保留验证缺口，不标记已验证。
